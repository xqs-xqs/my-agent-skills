# Agent 标准流程

目标：用户的时间只花在需要判断的地方，其余 Agent 自己推进。用户觉得自己在机械地贴指令、点合并，通常是因为流程里有他判断不了的关口。

1. **三份文件各管一件事**：需求文档管做什么；里程碑文档管怎么拆、技术约定、进度、留给后面的问题；CLAUDE.md 只放不说就会犯的红线和常用命令。同一件事只写在一处，否则改了一处，另一处就成了假话。
2. **从最轻的流程开始**：一个阶段一个 PR，阶段内一个里程碑一个 commit，计划说完就开工。没跑过的流程容易定重，所以规则只在出过一次问题之后才加，并写明是哪次问题。
3. **停下来问用户只有两种情况**：会改变已存数据或做完难回头；需求文档没写、又没有明显合理的做法。一个阶段的问题一次问完。其余自己定，做完在 PR 说明里列出。
4. **每个要用户点头的关口都要带信息**：关口上放的必须是用户能判断的东西（一条能亲手做的检查、一个用“用户会看到什么”描述的取舍）。用户判断不了的关口删掉，换成自动检查（lint、类型、测试、构建）。删关口的前提是发布前自动备份、能回退。
5. **推送前跑的和 CI 跑的是同一组命令**，写在 CLAUDE.md。
6. **会话之间靠文档交接**：新会话先读三份文件；新约定、和计划不一样的做法及原因、留给后面的问题，都在同一个 PR 里写回里程碑文档。
7. **每个阶段结束问一次**：这一阶段用户做的操作里，哪些没有用到判断？能自动的自动掉，不能的合并成一次。
