# 🍳 从零学做菜 (Cook From Zero)

> 不只给你一份菜谱，而是让你搞懂每一步为什么这么做——并且能把它用到下一道菜上。
> 同时刻意控制篇幅，确保你读完就能开火，而不是被文字劝退。

---

## 解决什么问题

普通菜谱的三个毛病：

| 毛病 | 后果 |
|------|------|
| 只给步骤不给原理 | 换一道菜又要从头查，能力不累积 |
| 抄时间参数（"煎 90 秒"） | 编码的是别人的锅和灶，你照做必翻车 |
| 一上来就追求完美 | 读完 3000 字，决定"明天再说" |

本 Skill 针对这三点，各设了一个硬机制。

---

## 三条铁律

### 1. 行动优先于完备
- **L1（最小可行版）硬上限 5 条**，超了就是把提升项塞进了必做项
- 主流程后插一行**阅读分界线**：*"读到这里就够了，去做。下面的等你做过一次再回来看"*
- 分界线以上必须完整可执行

### 2. 感官信号 > 时间参数
每个关键判断点都要给不依赖设备的可观察信号，时间只作参考。

> ❌ 煎 90 秒后翻面
> ✅ 轻推能滑动就翻面（约 90 秒，视锅温）

### 3. 指令与原理物理分离
步骤行只写"做什么"，原理挂在 `>` 引用块里、语法上可跳过。

**自检：删光所有原理块，剩下的步骤还能独立做出这道菜吗？** 不能就说明关键信息藏错了地方。

---

## 输出结构

```
1. 核心矛盾            一句话说清这道菜难在哪
2. L1 关键变量         ≤5 条硬变量 + 明确的"这一版能到什么水平"
3. 主流程              步骤 + 可跳过的原理批注，坑就地绑定
   ——— 阅读分界线 ———
4. L2 提升项           标注成本：免费 / 花钱 / 花时间
5. 翻车诊断表          症状 → 原因 → 当场补救 → 下次预防
6. 扩展与边界          横向迁移 / 纵向进阶 / 原理何时失效
7. 带走的东西          checklist + 空白参数表
```

分界线以上 ≤1200 字，全文 ≤3000 字。

---

## 两个设计细节

**约束前置。** 开头先确认**锅具 / 热源 / 已有调料 / 时间预算**。没有约束的输出是通用菜谱，有约束的才是给这个人的方法——"你只有一个 28cm 铸铁锅"能直接否掉焯水和整鸡浸熟两套方案。

**空白参数表。** 结尾给一张表让你填自己的火力档、时长、读数。**记三次，你就有了匹配自己厨房的参数，比任何菜谱都准。** 这是"复用"真正发生的地方。

---

## 触发方式

装上后自动触发。典型场景：

- "我买了半只鸡和一盒鸡胸，怎么料理"
- "牛排到底怎么解冻 / 熟成是什么意思"
- "为什么我煎的肉总是粘锅"
- "葱姜蒜夏天怎么存"

也可以显式调用：`用 cook-from-zero 教我做红烧肉`。

---

## 不适用

**烘焙、精确发酵类。** 这类是"前期精确配比 + 中途不可干预"，而本 Skill 的骨架建立在"感官反馈 + 中途调节"上。触发时会主动说明差异，但别指望它写出好的吐司配方。
