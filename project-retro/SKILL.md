# 项目复盘提取

复盘的产出是下一个项目的默认做法。读起来有道理、但没有改掉任何默认做法的结论，下个项目里不会生效。

材料只用仓库里查得到的：提交历史、PR 说明、需求文档和里程碑文档的改动记录。每条结论指到具体的提交或文件，指不到的不写。

开始前先问用户三句话：最不满意的是什么、最满意的是什么、重来会先做什么。提取围绕这三句展开，因为哪里难受只有用户知道，从仓库里推不出来。

输出四段：

1. **路径**：实际的先后顺序和时间线；第一次能真实使用是在哪一步；哪些事卡在等待上。
2. **改过的决定**：中途改了的流程、约定、数据结构。原来怎样、改成怎样、哪件事触发的。
3. **下次的默认做法**：每条写成“下次在〔什么时候〕做〔什么〕”，并指明改哪个 skill 或模板的哪一行。写不成这个形式的不算结论。
4. **概念索引**：项目用到的后端和系统设计概念，每个一行：防的是什么问题、在项目里的位置、通用叫法。位置要在仓库里查得到。

不写：对模型的话术技巧、会随工具版本变的操作细节、对用户的性格评价。前两样换个模型或版本就过期，第三样读了也不改变做法。
